# com.apple.macl 权限保留适配器（clonefile 临时索引）

关联 [Issue #5](https://github.com/mcncarl/jianying-headless/issues/5)。本文件说明
`publish()` 临时索引准备的权限保留机制与已验/未验边界。
判定规则本身没有放宽；本文不描述也不支持任何忽略 `com.apple.macl`、
按长度放行、删除属性或关闭 SIP/TCC 的方案。

## 背景

以下是限定环境中的观测，不是对系统内部机制的结论：在受影响的 macOS 27 机器上，
草稿根目录里**直接新建**的文件会带上 `com.apple.macl`，该属性用户态不能写也不能删。
原首页索引由剪映创建，不带它；因此新建的临时索引无论如何复制属性都无法与
原索引逐属性一致，`copy_xattrs` 的严格判定会拒绝（这是正确的失败方向）。

## 机制

`publish()` 准备临时索引时（`engine/jy14_headless.py` 的 `publish`）：

1. 首页索引先经事务快照读取；它是符号链接或非普通文件时，在 `locked` 阶段即拒绝。
2. 用 `clonefile(2)` 把原首页索引克隆为临时文件，带 `CLONE_NOFOLLOW`，不跟随符号链接。
3. 覆写前用 fstat 确认临时文件是普通文件、链接数为 1、且不是原索引的 inode，
   再截断并写入新索引内容。
4. 仅在克隆**明确不受支持**（`errno.ENOTSUP`，例如非 APFS 卷）时回退到
   原先的直接新建路径，过同一道判定门；权限、目标已存在等其余错误直接失败，
   不静默回退。
5. 覆写后照常执行 `copy_xattrs`：仍只容忍 `com.apple.provenance` 值变化
   且两侧均存在；`com.apple.macl`、`com.apple.quarantine` 及任何属性的
   出现、消失或变化仍拒绝。提交前复查与失败恢复逻辑不变。
6. 审计 `prepared.json` 与失败时的 `failure.json` 记录 `prepared_via`（`clonefile`、`create`
   或尚未准备），门禁报错也附带该信息，不伪报完整保留。

## 已验 / 未验

贡献者环境报告（维护端审阅时未复现）：macOS 27.0 arm64、剪映 11.5.0。原生链路证据
对应 f17bd8f：两条真实草稿完成 build → publish → 剪映打开/播放/编辑/保存/完全退出/冷重开
→ 回读，最终索引属性为 `{provenance, quarantine}`、无 macl，既有首页条目不变。
单元测试对应 40666f9。

维护端（2026-10-18，macOS 27.0 26A428、剪映 11.6.0，日常首页、已克隆备份 `User Data`）：
剪映运行过一次后，Claude 与 Terminal.app 两种宿主在草稿根直接新建的文件都带上了 macl，
clonefile 副本则保留原索引的属性集合。用候选 40666f9 的准备方式完成 10 次首页登记，
均经界面打开、播放、保存、冷重开与两次回读（见 #31 的验证记录）。

真实文件系统测试（macOS）：目标已存在时返回 EEXIST 且原字节不变；符号链接源只克隆链接本身，
经它覆写返回 ELOOP；首页索引是符号链接时在 `locked` 阶段拒绝且无任何写入；
新内容短于原文件时覆写结果精确；原索引或其硬链接不会被截断；真实克隆完成整条登记。

未验：其他机器与其他 macOS 版本；非 APFS 回退路径的真实环境（仅 mock 覆盖）；
隔离测试账户环境；公开 IG 案例在隔离环境的原生验收。原探针工具已从本 PR 拆出，
需按 #5 的要求（描述符相对的独占创建、显式开关与普通目录对照、夹具立即登记）另行提交。
